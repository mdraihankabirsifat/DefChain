# Threat model

| Threat                                            | Implemented mitigation                                                                     | Residual risk                                                                                                          |
| ------------------------------------------------- | ------------------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------- |
| Curious insider / fishing query                   | Active case, purpose binding, target validation, per-user budget, safe SecurityEvent       | Colluding insiders or fabricated local case data require organizational controls and oversight                         |
| Shared HMAC key compromise or linkability         | Domain + epoch separation, tokens off ledger/logs, separate local indexes                  | Equal identifiers remain linkable within an epoch; shared demo secret has broad blast radius                           |
| Compromised application user                      | bcrypt password hashes, short-lived JWT, active/revoked check, role/org checks, rate limit | Demo JWT revocation is checked through current user status but no production IdP/MFA/device assurance                  |
| Police forges RAB result/decision                 | Chaincode compares invoker MSP to providerOrg; provider Gateway path                       | A compromised RAB identity can produce RAB-backed false statements                                                     |
| Compromised agency peer                           | Multi-member ledger and immutable state                                                    | OR endorsement permits one valid peer endorsement for baseline availability; peer compromise needs governance response |
| Metadata/timing inference                         | Opaque case reference, narrow codes, no token/payload                                      | Organization, timing, purpose, scope, and match result remain visible to channel members                               |
| Payload interception/tampering                    | AES-256-GCM, fresh 96-bit IV, SHA-256 hash, Ed25519 signature, verification before display | Shared demo encryption secret is not production key exchange; endpoint compromise exposes plaintext                    |
| Adapter spoof/replay                              | Signed exact body, timestamp window, nonce cache, internal/loopback network                | In-memory nonce cache resets; no mTLS/service identity in demo                                                         |
| Malicious/incorrect source data or human decision | Audit identifies attesting/deciding organization                                           | Blockchain does not validate truth, identity correctness, guilt, legality, or decision quality                         |
| Ledger leakage                                    | Field minimization and decoded-block leakage script                                        | Allowed metadata still leaks; new schema fields require review and updated markers                                     |
| Denial of service                                 | Body/rate limits, timeouts, fail-closed behavior                                           | Small demo has no HA, queue, circuit breaker, or operational SLO                                                       |

Trust assumptions include secure host custody of demo keys, honest cryptographic libraries, correctly generated MSP material, and authorized control of each adapter database. These assumptions must be strengthened with HSM/KMS, mTLS, independent keys, monitored CAs/CRLs, hardened hosts, and formal incident response.
